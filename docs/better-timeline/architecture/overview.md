# Better Timeline Architecture Overview

This file is the fastest way to rebuild the mental model of the Better Timeline editor before making changes.

## What The Editor Is

Better Timeline is a first-class Blender space type (`SPACE_BETTER_TIMELINE`), not an add-on and not a mode layered on top of the stock Timeline. The core bootstrap lives in `source/blender/editors/space_better_timeline/space_better_timeline.cc`.

The editor is intentionally split into focused sibling modules:

- `space_better_timeline.cc` = space creation, region registration, lifecycle glue
- `better_timeline_data.cc` = data ownership, duplication, blend I/O, selection helpers, undo type
- `better_timeline_layout.cc` = geometry and hit-test helpers
- `better_timeline_draw.cc` = rendering
- `better_timeline_ops_tracks.cc` = track operators and track clipboard
- `better_timeline_ops_clips.cc` = clip operators and clip clipboard
- `better_timeline_ops_view.cc` = scrolling, splitter drag, view framing, keymap wiring
- `better_timeline_types.cc` = runtime registry for track/clip types
- `better_timeline_intern.hh` = shared internal contracts across these modules

## Region Model

The space creates three real Blender regions:

- `RGN_TYPE_HEADER` = Better Timeline header
- `RGN_TYPE_UI` = right sidebar (`Properties Pane`), hidden by default and toggled with `N`
- `RGN_TYPE_WINDOW` = main region containing both `Track List Pane` and `Timeline Canvas`

The main region is one region with two logical panes. The splitter is custom; the Properties Pane is not.

## Authoritative State

Persistent state lives on `SpaceBetterTimeline` in `DNA_space_types.h`.

- `tracks` owns the track list
- each `BetterTimelineTrack` owns its `clips`
- `selected_track_index` is the active/anchor track index
- `selected_clip_index` is the active clip expressed as a global clip index across all tracks
- `next_track_name_index` is the monotonic source for autogenerated track names
- `track_panel_width` stores Track List Pane width
- `track_scroll_offset` stores vertical scroll offset for track rows

Transient editor-only state lives in `SpaceBetterTimeline::runtime`, implemented as `SpaceBetterTimeline_Runtime` in `better_timeline_intern.hh`.

Current runtime overlays include:

- track reorder preview
- clip drag preview
- clip box-select preview
- clip resize preview

## Selection Model

Selection is split between per-item flags and active indices:

- tracks use `BetterTimelineTrack::selected`
- clips use `BetterTimelineClip::selected`
- `selected_track_index` and `selected_clip_index` keep the active/anchor items stable for range selection and sidebar context

Python UI should prefer `space.active_track` and `space.active_clip` from RNA instead of reimplementing selection lookup.

## Type System

Tracks and clips are typed from the start. The persistent identifiers are string idnames:

- `BetterTimelineTrack::track_type`
- `BetterTimelineClip::clip_type`

The registry in `better_timeline_types.cc` resolves those idnames into descriptors with labels, descriptions, colors, icons, and compatibility behavior.

Compatibility is a model rule, not a UI hint. All create/move/paste/duplicate/property edits must use the centralized API in `ED_better_timeline.hh`.

## Two Core Invariants

- There is no detached global clip store. Track ownership is authoritative.
- Type-specific payload belongs in `track->properties` / `clip->properties`, not in ad hoc hardcoded fields.

## What Usually Changes Together

- model or persistence change: `DNA_space_types.h` + `better_timeline_data.cc` + RNA if UI needs access
- input change: `better_timeline_ops_*` + `better_timeline_layout.cc` hit-tests + docs
- visual change: `better_timeline_draw.cc` + maybe `better_timeline_layout.cc`
- new editor integration: files under `source/blender/editors`, `makesrna`, `scripts/startup/bl_ui`, or undo registration
